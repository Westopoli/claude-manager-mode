# A7 — E2E mini-cascade through the new worktree machinery

Driven directly against `skills/swarm-shared/scripts/worktree_ops.py` and `run_gates.py` (installed versions, not copies) in a throwaway git repo under scratchpad. Two leaves (`add_impl.py`, `mul_impl.py`), one umbrella that imports both. No subagents — this exercises the mechanism itself, which is already unit-tested; the point of E2E is that the *sequence* a real cascade would run, end to end, produces a correct git history and a correct user checkout.

## Sequence run

1. `preflight --slug e2e` → clean, no leftovers.
2. `base --slug e2e --wave 1` → base sha recorded, `swarm/e2e/integration` created.
3. `add --slug e2e --wave 1` → two worktrees, both `HEAD == base`.
4. Simulated leaves: ran `pytest` directly on each worktree's test file to confirm RED (`ModuleNotFoundError`), wrote the impl file, confirmed GREEN — exactly the loop the leaf prompt specifies. No git commands from the "leaf" side.
5. `commit --slug e2e --leaf leaf-01` / `leaf-02` → each leaf's impl committed on its own branch.
6. `run_gates.py --leaf leaf-01` → correctly **blocked** on missing `wave-1.SWEEP.md` (Phase 5.2 never ran in this minimal fixture) — the A2 precondition working as designed. Wrote the sweep file; re-ran → clear to admit. `6.3 file-match`, `G1 parent-owned`, `G5 footprint` all **PASS** against real git diffs.
7. `admit --slug e2e --leaf leaf-01` → because the fixture's umbrella imports both modules at module scope, a single-leaf merge can't move the umbrella's pass count (0→0) — correctly detected as the **6.8 same-count yellow flag**, merge left in place, exit 3, "ask the user" message. This is real behavior, not a bug: it is exactly the two-part-umbrella boundary case the gate is designed to surface.
8. `admit --slug e2e --leaf leaf-02` (before resolving leaf-01) → correctly **refused by 6.0 bypass detection**: leaf-01 has no log row yet (its merge is pending confirmation), so leaf-02 cannot proceed. Confirms bypass detection reads real state, not optimistic state.
9. `admit --slug e2e --leaf leaf-01 --confirm-same` → admitted, log row `+0 (confirmed)`, leaf-01 worktree/branch removed.
10. Re-ran `run_gates.py --leaf leaf-02` → now clear (`6.0 bypass` PASS: "1 prior leaf/leaves each have a row and evidence").
11. `admit --slug e2e --leaf leaf-02` → real regression check: umbrella pre=0, post=2, **delta +2**, genuinely admitted. Integration worktree afterward contains both impl files; `pytest` run there passes 2/2.
12. **Checked the user's checkout at this point**: `src/` still holds only `__init__.py` + `contract.py` — no leaf output has touched it. Confirms the isolation property end to end, not just per-unit-test.
13. `finish --slug e2e` (no `--yes`) → shows the four pending commits (2 leaf commits + 2 merge commits), refuses, exit 3.
14. `finish --slug e2e --yes` → fast-forwards `main` to integration, removes the integration worktree + branch, prints residual = none.
15. **User checkout after finish**: `src/` now has `add_impl.py` and `mul_impl.py`. `git log --graph` shows a clean history — both `--no-ff` merge commits preserved, base commit intact, no rebasing.
16. `status --slug e2e` → "(none)"; `git branch -a` → only `main`. Nothing leaked.
17. `python3 -m pytest tests/test_umbrella.py -q` run directly on the real checkout (no worktree involved) → **2 passed**. The umbrella genuinely passes on the user's own tree, not just inside a sandbox.

## What this confirms about Track A

- File-match, G5 footprint, and the overlap check all operate correctly against real `git diff`/`git status` output, not a mocked git.
- Bypass detection (6.0) correctly blocks a leaf whose predecessor's admission is still pending — this is a scenario the unit tests didn't cover (they test bypass across *fully resolved* prior leaves) and it worked on the first real run.
- The same-count yellow flag (6.8) fires correctly on a realistic two-part-umbrella shape and leaves the merge inspectable rather than silently discarding it.
- The user's checkout is untouched until the single confirmed `base` commit and the single confirmed `finish` fast-forward — verified by direct inspection of `src/` at each stage, not just by reading the code.
- `git log --graph` after `finish` is exactly the audit trail the design promises: two merge commits, two leaf commits, base — real commit history, not squashed or rebased.

## Deviations from the unit tests worth noting

- The unit test suite's fixtures always resolve every leaf fully before gating the next one; this run hit the pending-confirm-same → bypass-block interaction for the first time and it worked without any code change.
- No deviation required any change to `worktree_ops.py` or `run_gates.py` — the E2E run passed against the code as committed in `e449198`/`207b0cf`.
